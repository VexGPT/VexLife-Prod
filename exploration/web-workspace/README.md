# VexLife canonical Companion workspace — lived exploration threshold

`[VXG RealForever]`

This directory preserves a **lived exploration threshold** for the intended VexLife nested-browser + companion experience. It is deliberately kept under `exploration/` so it can preserve a working human surface without claiming to replace the accepted VexWeb authoring/compiler trajectory.

## What this threshold establishes

~~~text
hand-built VexLife presentation
-> bounded public nested browser
-> current VexLife Companion availability
-> canonical self-development Conversation projection
-> human Send
-> current VexLife streaming turn
-> durable canonical Conversation advance
~~~

The presentation is a consumer. Current VexLife remains the owner of Conversation, prompt/Memory composition, Companion/model/runtime lifecycle, and durable message truth.

~~~text
THIS PRESENTATION != CONVERSATION OWNER
THIS PRESENTATION != MODEL RUNTIME OWNER
VISIBLE PAGE != CONTEXT SUPPLIED TO VEX
BROWSER CONTEXT RECEIPT != PROMPT CONTEXT AUTHORITY
EXPLORATION THRESHOLD != VEXWEB F2 GENERATED PRODUCT
~~~

## Current truthful boundaries

- The nested browser can render/navigate bounded public pages and form source-addressed browser-context receipts.
- Those browser-context receipts are **not yet admitted into the canonical prompt/context owner**. If the human includes the page, Send is held visibly rather than silently concatenating page text into the prompt.
- Clean-chat/reset is **not yet connected**. The button remains as intended UI, but the presentation refuses to pretend it owns canonical Conversation reset/archive semantics.
- Exact canonical prompt/context usage is **not yet exposed to this presentation**. Settings therefore says `Not exposed yet` rather than inferring context usage from local rendering or model internals.
- VexLife Home, Continuity Mode and Dream Sync remain unbound here.
