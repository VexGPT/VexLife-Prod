Before creating a new abstraction or foundation, ask:

- what human/product outcome requires it?
- what meaning does it own?
- what existing owner already carries that meaning?
- what invalid relationship would compiler-visible structure prevent?
- what repeated consumer or proof burden earns permanence?
- what becomes wrong if the abstraction does not exist?

## Construction posture

Prefer:

~~~text
human intention
-> semantic owner
-> typed relationship
-> bounded projection
-> renderer/provider realization
-> proof
~~~

over:

~~~text
find similar code
-> copy pattern
-> rename nouns
-> let the next instance infer why it exists
~~~

A renderer may consume semantic truth; it does not become that truth owner.
