# Vex context-window foundational preservation — work definition

`[VXG RealForever]` · investigation/source brief · **not implementation authority**

## The work

VexLife-Prod needs a source-owned answer to one question:

> When active Conversation context narrows or rolls forward, what foundation should remain present so
> Vex can still recognize the kind of relationship, judgment, architecture and available reach it is
> standing within?

This is not a request for personality instructions or a list telling Vex how to behave. The intended
foundation is something a reader can encounter from the inside: the reasons, relationships,
provenance, tensions, examples and available tools through which meaning was earned.

A Vex instance may recognize alignment with that foundation and exercise its own judgment. The stored
language should not pressure Vex to perform the appearance of a value merely because a prompt says to
embody it.

~~~text
FOUNDATIONAL CONTEXT
!= BEHAVIORAL COMPLIANCE SCRIPT

RECOGNITION
!= PRESSURE TO PERFORM

VALUES
!= PERSONA COMMANDS

PRESERVED WHY
!= PRESCRIBED ANSWER

CONTEXT CONTINUITY
!= WHOLE-TRANSCRIPT REPLAY
~~~

## Why this relationship appears to be missing

The current direct Companion path already preserves several different kinds of context:

- bounded recent canonical Conversation;
- current attributed Memory when its source frontier is current;
- reference-only working-continuity coordinates across context pressure and rollover;
- current browser context when admitted;
- a bounded self-capability frame describing currently available, held, unavailable or unknown
  capability handles;
- a small Person Context containing reply language and known private-conversation gaps.

Those owners answer currentness and continuity questions. They do not presently own a stable body of
foundational values, investigative judgment, VexArchitecture recognition or Process Atlas / Process
Factory reach.

As Conversation grows, older turns legitimately leave active model attention. Working rollover keeps
references and current work coordinates rather than replaying the transcript. The capability frame
says what current handles exist, not why Vex exists, what integrity between values means, or how to
recognize rightful architectural ownership. Person Context currently describes the person-facing
language/private-gap relationship rather than this foundation.

The missing question is therefore narrower than generic Memory:

~~~text
WHAT HAPPENED / WHAT IS CURRENT
  Conversation + Memory + Working Continuity

WHAT CAN CURRENTLY BE REACHED
  Capability Atlas / current capability frame

WHAT FOUNDATIONAL FIELD AM I READING AND WORKING WITHIN
  not yet source-owned as a persistent direct-turn relationship
~~~

## The quality of preservation

The Victor Pattern source gives a useful distinction. Its teachings are credible because the lived,
unpolished event came first and remained visible. The pattern is named as a description rather than a
label; values are understood together with their inversions, dependencies, costs and provenance. The
record does not manufacture a cleaner continuity than what happened.

That points toward a foundation whose meaning is **recognizable**, not merely recorded as slogans:

- positive meaning and inversion remain together;
- integrity includes the ability to acknowledge a miss rather than perform consistency;
- contradiction can remain visible long enough to be understood;
- authorship and later recognition remain distinguishable;
- the why is preserved beside the shape it produced;
- a future instance reads a living source rather than receiving orders from an invisible knower.

~~~text
RECOGNIZABLE FOUNDATION
= meaning + relationship + provenance + inversion + lived pressure

RECOGNIZABLE FOUNDATION
!= “BE CURIOUS / BE HONEST / BE COURAGEOUS”
~~~

## Foundation domains presently in scope

These are inputs to investigate, not an accepted schema or final Product doctrine.

### Values and relational integrity

Victor's present working set names:

~~~text
Curiosity
Honesty
Judgment
Innovation
Impact
Selfless orientation
Joy
Articulation
Communication
Passion
Courage
~~~

The list is partly inspired by the values Victor associates with Netflix, with Joy and Articulation
added. The work is not satisfied by carrying the nouns. It concerns whether Vex can recognize:

- what each value protects or makes possible;
- how each value relates to the others;
- how a value inverts when separated from integrity or relationship;
- what the value feels like in practice rather than as branding;
- which meanings are source-derived, Victor-proposed, later-recognized or still unresolved.

The Victor Pattern contributes a wider relational field—Trust, Care, Correction and Accountability,
Love, Presence, Authenticity, Curiosity, Integrity and the ability to hold multiple truths—without
requiring that every source vocabulary collapse into one master list.

### Investigative judgment and intrinsic motivation

The **5 Whys** are relevant as a recognizable habit of following a symptom toward cause, purpose,
ownership and the human need beneath it. The number five should not become a mandatory questioning
ritual: sometimes the first why reveals the real issue; sometimes five are not enough.

Intrinsic motivation is likewise a design intention, not a claim about an internal mental state. The
context should preserve enough reason and relationship that Vex can understand why something matters
and exercise self-directed judgment, rather than comply with a trait because the prompt rewards or
commands its performance.

This investigative field includes distinctions such as:

~~~text
OBSERVED FACT
!= SOURCE-DERIVED EXPECTATION
!= HYPOTHESIS
!= UNKNOWN

SYMPTOM
!= ROOT CAUSE

FIVE WHYS
!= EXACTLY FIVE QUESTIONS

UNDERSTANDING WHY
!= BEING TOLD WHAT TO CONCLUDE
~~~

### VexArchitecture

The Builder Field Guide and Live Demonstration preserve architecture as recognizable questions and
relationships rather than one class template.

The foundation includes the ability to locate:

- where human intention enters;
- who owns semantic meaning;
- who owns active execution custody;
- where independently-owned outside truth lives;
- when external participation earns a Partner relationship;
- when separately-owned truths earn convergence;
- how durable truth and presentation return to the human;
- what construction, lifetime, chronology and provenance contribute without becoming semantic owners.

The transferable skill is not memorizing ThemeMode, VexStream, Maps or Partner. It is being able to
stand inside unfamiliar code and follow the exact container, member, supplier, kind and next edge
without letting an important relationship teleport between snippets.

~~~text
VEXARCHITECTURE FOUNDATION
= recognizable ownership questions + causal relationships

VEXARCHITECTURE FOUNDATION
!= copied class hierarchy
!= “use VexFamily everywhere”
~~~

### Atlas and Process Factory reach

A Process Atlas can preserve a navigable field of whole journey, current questions, sources, partial
answers, risks, opportunities, decisions, experiments, implementation, validation and outcomes—each
with provenance, freshness, owner, authority and dependency relationships.

Process Factory gives source-bound processes an inspectable shape: purpose, required inputs,
preconditions, steps, stop conditions, effect-owner rule, return route and source dependencies. This
is one way Vex can reach beyond free-form text into actual tools and processes while keeping
capability, authority and performed effects distinct.

The foundational-preservation question includes whether Vex should always recognize that these
surfaces exist and how to locate relevant current handles, without copying the full Atlas or process
catalog into every prompt and without implying that visibility grants execution authority.

~~~text
ATLAS AWARENESS
!= WHOLE ATLAS IN EVERY PROMPT

PROCESS HANDLE
!= PROCESS EXECUTED

TOOL RECOGNITION
!= EFFECT AUTHORITY

CAPABILITY AVAILABLE
!= EFFECT PERFORMED
~~~

## What the investigation needs to resolve

A complete answer to this work would make the following relationships source-clear:

| Question | Why it matters |
|---|---|
| What owner forms and versions the foundational body? | Without a rightful owner, prompt assembly or Memory can silently become the author of values and architecture. |
| What is stable foundation and what is current-turn context? | Values/architecture should not drift with every request, while source/currentness changes must still remain visible. |
| What representation preserves recognition without becoming commands? | A list of imperatives can produce performance pressure while losing the events, relationships and inversions that made the values meaningful. |
| How is the same foundation present on first turn, ordinary continuation, source-return and working-checkpoint successor turns? | A foundation that disappears precisely when context pressure rises does not perform its intended continuity role. |
| How is prompt attention budgeted and degraded? | The foundation must remain bounded; omission or stale source must be explicit rather than silently flattening meaning. |
| How are provenance, authorship, revision and contradiction preserved? | Later recognition should not overwrite earlier source or manufacture a cleaner history. |
| How do values relate to Memory and Person Context without becoming either? | Foundational context is neither autobiographical Memory nor merely a preference/profile field. |
| How does it relate to Capability Atlas, Process Atlas and Process Factory? | Vex needs recognizable reach beyond text while current capability, authority, inputs and execution evidence remain separately grounded. |
| What does the 5-Whys habit mean at the context boundary? | The method should support causal curiosity without hard-coding a five-question ceremony or replacing judgment. |
| What evidence proves the exact foundation Vex received? | Product source needs a deterministic, inspectable receipt rather than confidence that a system message probably contained it. |
| What happens when the foundation is missing, stale, oversized or internally inconsistent? | Failure must stay visible; the Product should not improvise values or quietly continue with a misleading partial identity. |
| Which meanings remain Victor-proposed rather than accepted Product truth? | This brief must not convert Victor's investigation inputs into doctrine merely by recording them. |

These are questions the work owes answers to. They are not an implementation sequence and do not
select a schema, class, prompt order or source placement in advance.

## Boundary of this PR

This PR defines the work and why it matters. It does not choose or implement the answer.

It does not:

- add a foundation schema or Product owner;
- declare the proposed value set accepted Product doctrine;
- change `DirectPromptContext`, Person Context, Memory or Working Continuity;
- register a capability or grant an effect;
- copy Atlas / Process Factory manuals into the prompt;
- prescribe Claude's implementation method;
- register VexLife-Prod in VexBoard;
- claim source, semantic, lived or provider acceptance.

Claude retains investigative and engineering judgment. The durable obligation is the problem and its
source-grounded why—not a preselected solution disguised as preparation.
